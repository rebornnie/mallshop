## 功能一：订单并发安全优化

### 1.1 问题背景

当前订单创建流程中，库存扣减逻辑存在并发安全隐患：

```java
// 当前代码（存在并发问题）
PmsSkuStock skuStock = skuStockMapper.selectOne(stockWrapper);  // 步骤1: 读取库存
if (skuStock.getStock() - skuStock.getLockStock() < quantity) {  // 步骤2: 判断
    return CommonResult.failed("库存不足");
}
PmsSkuStock updateStock = new PmsSkuStock();
updateStock.setLockStock(skuStock.getLockStock() + quantity);    // 步骤3: 更新
skuStockMapper.updateById(updateStock);
```

**问题分析：**
- 步骤1和步骤3之间存在时间窗口，多个线程可能同时读取到相同的库存值
- 假设库存为10，两个线程同时读取到stock=10, lockStock=0
- 两个线程都判断10-0 >= 5，都执行更新lockStock=5
- 实际扣减了10个库存，但只锁定了5个，导致超卖

### 1.2 业务需求

**核心目标：** 在高并发场景下（如促销活动、秒杀），确保库存扣减的原子性，防止超卖。

**具体需求：**

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| STOCK-001 | 使用Redis Lua脚本实现原子性库存预扣 | 高 |
| STOCK-002 | 支持库存回滚（订单取消时返还） | 高 |
| STOCK-003 | 支持批量扣减多个SKU库存（事务性） | 中 |
| STOCK-004 | Redis库存与数据库库存的最终一致性 | 中 |
| STOCK-005 | 库存初始化（商品上架时加载到Redis） | 中 |
| STOCK-006 | 库存同步（定时从数据库同步到Redis） | 低 |

### 1.3 技术方案

**方案选择：Redis Lua脚本 + 数据库乐观锁双重保障**

```
┌─────────────────────────────────────────────┐
│              订单创建流程                      │
├─────────────────────────────────────────────┤
│ 1. 校验商品状态（是否下架）                    │
│ 2. Redis Lua脚本预扣库存（原子操作）           │
│    ├─ 成功: 继续创建订单                      │
│    └─ 失败: 返回库存不足                      │
│ 3. 创建订单（数据库事务）                      │
│ 4. 数据库乐观锁扣减库存（最终一致性）           │
│ 5. 发送延迟消息（订单超时取消）                │
└─────────────────────────────────────────────┘
```

**Lua脚本设计：**

```lua
-- 扣减库存脚本
local key = KEYS[1]           -- stock:sku:{skuId}
local quantity = tonumber(ARGV[1])  -- 扣减数量

local stock = redis.call('GET', key)
if not stock then
    return -1                 -- 库存不存在
end

stock = tonumber(stock)
if stock < quantity then
    return -2                 -- 库存不足
end

redis.call('DECRBY', key, quantity)
return stock - quantity       -- 返回剩余库存
```

**数据库乐观锁设计：**

```sql
-- 使用version字段实现乐观锁
UPDATE pms_sku_stock 
SET stock = stock - #{quantity}, 
    lock_stock = lock_stock + #{quantity},
    version = version + 1
WHERE sku_id = #{skuId} 
  AND stock - lock_stock >= #{quantity}
  AND version = #{version}
```

## 功能二：秒杀系统

### 2.1 业务背景

秒杀是电商平台的核心营销工具，通过限时、限量、低价商品吸引流量，提升平台活跃度和用户转化。秒杀场景的特点是：瞬间高并发、库存有限、时间窗口明确。

### 2.2 业务需求

**核心目标：** 实现一个高并发、防超卖、用户体验良好的秒杀系统。

**功能需求：**

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| SECKILL-001 | 秒杀活动管理（后台创建/编辑/删除） | 高 |
| SECKILL-002 | 秒杀商品配置（关联商品、设置秒杀价、库存） | 高 |
| SECKILL-003 | 秒杀活动列表展示（前台） | 高 |
| SECKILL-004 | 秒杀商品详情页（倒计时、库存显示） | 高 |

| SECKILL-006 | 秒杀订单查询 | 中 |
| SECKILL-007 | 秒杀活动数据统计 | 中 |

| SECKILL-009 | 秒杀结果通知（成功/失败） | 低 |

### 2.3 技术方案

**架构设计：**

```
┌─────────────────────────────────────────────────────┐
│                    用户请求                          │
│  ├─ 活动列表/详情页（直接查询Redis缓存）              │
│  └─ 秒杀下单（限流 + Redis预扣 + 异步队列）           │
├─────────────────────────────────────────────────────┤
│  Nginx限流（令牌桶）                                 │
├─────────────────────────────────────────────────────┤
│  秒杀服务                                            │
│  ├─ 验证码校验                                       │
│  ├─ 用户资格校验（是否已秒杀）                        │
│  ├─ Redis Lua预扣库存                                │
│  └─ 发送MQ消息（异步创建订单）                        │
├─────────────────────────────────────────────────────┤
│  RabbitMQ（订单创建队列）                             │
├─────────────────────────────────────────────────────┤
│  订单服务（消费MQ，创建订单）                         │
│  ├─ 数据库乐观锁扣减库存                              │
│  └─ 订单创建成功/失败回调                             │
└─────────────────────────────────────────────────────┘
```

**核心流程：**

```
1. 用户进入秒杀活动页
   └─ 查询Redis缓存的活动信息
   
2. 用户点击"立即秒杀"
   ├─ 校验验证码（图形/滑块）
   ├─ 限流检查（令牌桶/漏桶）
   ├─ 检查用户是否已秒杀（Redis Set）
   ├─ Redis Lua预扣库存
   │   ├─ 成功: 生成秒杀令牌，返回"排队中"
   │   └─ 失败: 返回"已售罄"
   └─ 发送MQ消息（异步创建订单）
   
3. 用户轮询秒杀结果
   ├─ 查询Redis中的订单创建状态
   ├─ 成功: 跳转订单支付页
   └─ 失败: 提示失败原因
   
4. 订单服务消费MQ
   ├─ 数据库乐观锁扣减库存
   ├─ 创建订单
   ├─ 更新Redis状态
   └─ 发送通知（成功/失败）
```

## 功能三：优惠券系统

### 3.1 业务背景

优惠券是电商平台的常用营销工具，通过发放优惠券刺激用户消费，提升客单价和复购率。优惠券类型包括满减券、折扣券、无门槛券等。

### 3.2 业务需求

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| COUPON-001 | 优惠券模板管理（后台创建/编辑/删除） | 高 |
| COUPON-002 | 优惠券类型（满减/折扣/无门槛） | 高 |
| COUPON-003 | 优惠券领取（前台用户领取） | 高 |
| COUPON-004 | 优惠券使用（订单结算时选择） | 高 |
| COUPON-005 | 优惠券过期自动失效 | 高 |
| COUPON-006 | 使用限制（每人限领/总量限制/有效期） | 中 |
| COUPON-007 | 适用商品范围（全店/指定分类/指定商品） | 中 |
| COUPON-008 | 优惠券列表（我的优惠券） | 中 |
| COUPON-009 | 后台优惠券数据统计 | 低 |

### 3.3 技术方案

**优惠券计算规则：**

```
满减券: 订单金额 >= 门槛金额 ? 订单金额 - 优惠金额 : 不满足
折扣券: 订单金额 * 折扣率（最高优惠上限）
无门槛券: 订单金额 - 优惠金额（最低订单金额限制）

叠加规则: 单笔订单只能使用一张优惠券
优先级: 优惠力度最大的优先推荐
```

## 功能六：接口限流防刷

### 6.1 业务背景

防止恶意攻击和滥用，保护系统资源，确保正常用户的访问体验。

### 6.2 业务需求

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| RATE-001 | 登录接口限流（5次/分钟） | 高 |
| RATE-002 | 注册接口限流（3次/分钟） | 高 |
| RATE-003 | 验证码发送限流（1次/分钟） | 高 |
| RATE-004 | 通用API限流（100次/分钟/用户） | 中 |
| RATE-005 | IP黑名单（异常行为） | 中 |
| RATE-006 | 图形验证码（登录/注册） | 中 |

### 6.3 技术方案

**基于Redis的令牌桶算法：**

```
Key: rate_limit:{api}:{userId/ip}
Value: 令牌数量
TTL: 1分钟

算法:
1. 获取当前令牌数
2. 如果 > 0，扣减1，允许通过
3. 如果 = 0，拒绝请求，返回429
4. 每分钟重置令牌数
```

### 6.4 测试场景

| 测试编号 | 场景 | 预期结果 |
|---------|------|---------|
| TC001 | 正常频率登录 | 成功 |
| TC002 | 1分钟内登录6次 | 第6次失败，返回429 |
| TC003 | 1分钟后再次登录 | 成功，计数重置 |
| TC004 | 验证码发送间隔<1分钟 | 失败，返回发送太频繁 |
