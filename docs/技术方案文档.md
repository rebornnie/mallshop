## 一、技术架构总览

### 1.1 架构设计原则

本项目采用**分层架构 + 微服务模块化**设计，遵循以下原则：

- **高内聚低耦合**：按业务领域划分模块，模块间通过接口交互
- **防御式编程**：所有边界操作显式处理错误，不信任外部输入
- **性能优先**：热点数据走Redis缓存，复杂查询走Elasticsearch
- **数据一致性**：核心业务使用数据库事务，最终一致性场景使用MQ补偿

## 三、核心功能技术方案

### 3.1 订单并发安全优化

#### 3.1.1 问题分析

原库存扣减流程存在竞态条件：
```java
// 问题代码：读取-判断-更新非原子操作
PmsSkuStock skuStock = skuStockMapper.selectOne(stockWrapper);  // 步骤1: 读取
if (skuStock.getStock() - skuStock.getLockStock() < quantity) {  // 步骤2: 判断
    return CommonResult.failed("库存不足");
}
PmsSkuStock updateStock = new PmsSkuStock();
updateStock.setLockStock(skuStock.getLockStock() + quantity);    // 步骤3: 更新
skuStockMapper.updateById(updateStock);
```

**风险场景**：库存10，两个线程同时读取到stock=10, lockStock=0，都判断通过，最终锁定10但只扣减5，导致超卖。

#### 3.1.2 解决方案：Redis Lua + 数据库乐观锁双重保障

**第一层：Redis Lua原子预扣**

```lua
-- 单SKU扣减脚本
local key = KEYS[1]
local quantity = tonumber(ARGV[1])
local stock = redis.call('GET', key)
if not stock then return -1 end  -- 库存不存在
stock = tonumber(stock)
if stock < quantity then return -2 end  -- 库存不足
redis.call('DECRBY', key, quantity)
return stock - quantity  -- 返回剩余库存
```

**第二层：数据库乐观锁**

```sql
UPDATE pms_sku_stock 
SET stock = stock - #{quantity}, 
    lock_stock = lock_stock + #{quantity},
    version = version + 1
WHERE sku_id = #{skuId} 
  AND stock - lock_stock >= #{quantity}
  AND version = #{version}
```

**降级策略**：Redis不可用时，直接走数据库乐观锁扣减。

#### 3.1.3 Redis Key设计

| Key格式 | 示例 | 数据类型 | TTL | 说明 |
|---------|------|---------|-----|------|
| stock:sku:{skuId} | stock:sku:10001 | String | 永久 | SKU实时库存 |
| stock:lock:{orderSn} | stock:lock:ORDER123 | Hash | 30分钟 | 订单库存锁定记录 |

#### 3.1.4 核心流程

```
1. 校验商品状态（是否下架）
2. Redis Lua脚本预扣库存（原子操作）
   ├─ 成功: 继续创建订单
   └─ 失败: 返回库存不足
3. 创建订单（数据库事务）
4. 数据库乐观锁扣减库存（最终一致性）
5. 发送延迟消息（订单超时取消，30分钟）
6. 订单超时/取消时调用rollbackStock回滚Redis库存
```

### 3.2 秒杀系统

#### 3.2.1 架构设计

```
用户请求
  ├─ 活动列表/详情页 → 查询Redis缓存
  └─ 秒杀下单 → 限流 + 防重 + Redis预扣 + MQ异步

秒杀服务
  ├─ 验证码校验（预留）
  ├─ 用户资格校验（Redis Set，是否已秒杀）
  ├─ Redis Lua预扣库存（原子操作）
  └─ 发送MQ消息（异步创建订单）

订单服务（消费MQ）
  ├─ 数据库乐观锁扣减库存
  ├─ 创建订单
  ├─ 更新Redis秒杀结果
  └─ 发送通知（成功/失败）
```

#### 3.2.2 核心机制

**防重复秒杀**：使用 `setIfAbsent` 设置24小时过期标记
```java
String key = "seckill:user:" + flashId + ":" + memberId;
Boolean success = redisTemplate.opsForValue().setIfAbsent(key, "1", 24, TimeUnit.HOURS);
```

**秒杀结果缓存**：记录PROCESSING/ SUCCESS/ FAILED状态，30分钟过期
```java
String resultKey = "seckill:result:" + flashId + ":" + memberId;
redisTemplate.opsForValue().set(resultKey, "PROCESSING", 30, TimeUnit.MINUTES);
```

#### 3.2.3 Redis Key设计

| Key格式 | 示例 | 数据类型 | TTL | 说明 |
|---------|------|---------|-----|------|
| seckill:stock:{flashId}:{skuId} | seckill:stock:1:10001 | String | 活动结束 | 秒杀库存 |
| seckill:user:{flashId}:{memberId} | seckill:user:1:20001 | String | 24小时 | 用户已秒杀标记 |
| seckill:result:{flashId}:{memberId} | seckill:result:1:20001 | String | 30分钟 | 秒杀结果 |
| seckill:products:{flashId} | seckill:products:1 | List | 活动结束 | 秒杀商品列表 |

#### 3.2.4 秒杀下单流程

```
1. 用户点击"立即秒杀"
2. 校验验证码（图形/滑块）
3. 限流检查（令牌桶/漏桶）
4. 检查用户是否已秒杀（Redis Set）
5. Redis Lua预扣库存
   ├─ 成功: 生成秒杀令牌，记录PROCESSING状态
   └─ 失败: 返回"已售罄"
6. 发送MQ消息（异步创建订单）
7. 用户轮询秒杀结果
   ├─ 查询Redis中的订单创建状态
   ├─ 成功: 跳转订单支付页
   └─ 失败: 提示失败原因
```

### 3.3 优惠券系统

#### 3.3.1 优惠券类型与计算规则

| 类型 | 编码 | 计算规则 | 示例 |
|------|------|---------|------|
| 满减券 | 1 | 订单金额 >= 门槛 ? 减免固定金额 : 0 | 满100减20 |
| 折扣券 | 2 | 订单金额 * 折扣率，有最大优惠上限 | 8折，最高减50 |
| 无门槛券 | 3 | 直接减免固定金额（最低订单金额限制） | 减30元 |

**叠加规则**：单笔订单只能使用一张优惠券
**优先级**：优惠力度最大的优先推荐

#### 3.3.2 核心计算逻辑

```java
private BigDecimal doCalculateDiscount(SmsCoupon coupon, BigDecimal orderAmount) {
    return switch (coupon.getType()) {
        case 1, 3 -> coupon.getAmount().min(orderAmount);  // 满减/无门槛
        case 2 -> {  // 折扣券
            BigDecimal discountRate = BigDecimal.ONE.subtract(coupon.getAmount());
            BigDecimal discount = orderAmount.multiply(discountRate);
            if (coupon.getMaxDiscount() != null) {
                discount = discount.min(coupon.getMaxDiscount());
            }
            yield discount.min(orderAmount);
        }
        default -> BigDecimal.ZERO;
    };
}
```

#### 3.3.3 领取流程

```
1. 校验优惠券状态（启用中）
2. 校验有效期（startTime <= now <= endTime）
3. 校验剩余数量（remainCount > 0）
4. 校验每人限领（已领数量 < perLimit）
5. 插入用户优惠券记录（@Transactional）
6. 扣减优惠券剩余数量
```

### 3.4 商品评价系统

#### 3.4.1 核心校验规则

```
1. 订单必须存在且属于当前用户

```

#### 3.4.2 评价统计算法

内存聚合计算，避免复杂SQL：
```java
long totalCount = commentList.size();
long starSum = 0;
long[] starCounts = new long[6];  // 索引1-5对应1-5星

for (PmsComment comment : commentList) {
    Integer star = comment.getStar();
    starSum += star;
    starCounts[star]++;
}

BigDecimal avgStar = BigDecimal.valueOf(starSum)
    .divide(BigDecimal.valueOf(totalCount), 1, RoundingMode.HALF_UP);
```

## 六、安全设计

### 6.1 认证机制

**JWT Token设计**：
```
Header: { "alg": "HS256", "typ": "JWT" }
Payload: { 
    "sub": "userId", 
    "iat": 1716700800, 
    "exp": 1717305600,  // 7天过期
    "roles": ["USER"] 
}
Signature: HMACSHA256(base64Url(header) + "." + base64Url(payload), secret)
```

### 6.2 接口安全

| 安全措施 | 实现方式 | 覆盖范围 |
|---------|---------|---------|

### 7.3 并发测试方案

```java
@Test
void concurrentDeductStock_ShouldNotOversell() throws InterruptedException {
    int threadCount = 100;
    int stock = 50;
    CountDownLatch latch = new CountDownLatch(threadCount);
    AtomicInteger successCount = new AtomicInteger(0);
    
    stockService.initStock(1L, stock);
    
    for (int i = 0; i < threadCount; i++) {
        executor.execute(() -> {
            try {
                boolean success = stockService.deductStock(1L, 1);
                if (success) successCount.incrementAndGet();
            } finally {
                latch.countDown();
            }
        });
    }
    
    latch.await();
    assertEquals(stock, successCount.get(), "库存50，成功次数应为50");
    assertEquals(0, stockService.getStock(1L), "最终库存应为0");
}
```
